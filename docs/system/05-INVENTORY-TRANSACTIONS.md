## 1. Inventory / Stock (คลังสินค้า)

### Products (สินค้า)
- `products-api.js` — CRUD products/categories/units/images
- `product-form.js` / `products-list.js` / `products-table.js` — สร้าง/แก้สินค้า + variant (parent-child ผ่าน `parent_id`); in-context CRUD units/categories ผ่าน ⚙️ modal
- variant ใช้ units ของ parent ถ้าไม่ override; รูป fallback ไป parent

### Categories / Units / Warehouses (master, in-context CRUD)
- `categories-list/form/api/table.js` — หมวดหมู่ (icon/สี/sort)

### Stock Balance / Dashboard / Report
- `stock-balance.html/.js` — **On-hand / Reserved / Available** ต่อ SKU + คลัง
  - **On-hand** = Σ signed qty จาก `stock_movements` (คำนวณสด ไม่เก็บ)
  - **Reserved** = (SO confirmed: ordered−delivered) + (REQ approved: approved−issued)
  - **Available** = On-hand − Reserved
  - variant group ใต้ parent; status badge ปกติ/ใกล้สั่ง/หมด/ติดลบ; toggle `inventory_allow_negative`
- `stock-dashboard.html/.js` — มูลค่ารวม (qty×cost), in/low/out-of-stock, top SKU, charts
- `stock-report.html/.js` — รายงาน (คอลัมน์จาก `js/shared/stock-fields.js`) + export
- `stock-initial-list.js` — ตั้งสต็อกเริ่มต้น (สร้าง movement type INIT)

### Movements (ความเคลื่อนไหว)
- `movements.html/.js` — บันทึก/ดู stock movement
  - **Signed qty:** IN/INIT/RETURN/ADJUST/TRANSFER → +qty ; OUT/INTERNAL → −qty
  - timeline ตามวันที่; ref_doc_type/id; lot_no/expiry (optional)

#### รูปแบบรายวัน (sql/180)
- **1 วัน = 1 ใบ (ต่อคลัง)** — ไม่มีการ "เปิดรอบ" เองแล้ว · เลื่อนวันด้วยแถบ
  `📅 วันที่นับ | ‹ วันนี้ › | 🏭 คลัง` (รูปแบบเดียวกับหน้า Daily Sale ของ CS)
- **แถบหัวเรื่องวันที่** `.sc-sheet-title` — "วันที่ 3 สิงหาคม 2569 · คลัง กทม. ชั้น3"
  ชุดสี/โครงเดียวกับ `.ds-sheet-title` ของ Daily Sale (ปี พ.ศ. เพราะเป็นเอกสารที่พิมพ์ไปใช้)
  · **ใบย้อนหลังเปลี่ยนเป็นแถบเทา** + ต่อท้ายสถานะ 🔒/🔓 — กันเผลอกรอกใส่ใบเก่า
  โดยไม่ทันสังเกตช่องวันที่ด้านบน
- **เปิดหน้า = สร้างใบของวันนี้ให้อัตโนมัติ** ถ้ายังไม่มี แล้ว **duplicate ทุกช่องจากใบล่าสุด**
  (ลัง/ชิ้น/ยืม/เบิก/ยอดระบบ/หมายเหตุ) + เติมสินค้าที่เพิ่งเพิ่มใน master
  **Why:** นับซ้ำที่เดิมทุกวัน ของส่วนใหญ่ไม่ขยับ — เริ่มจากใบเปล่าทุกวันคือพิมพ์ใหม่ 28 แถวทุกเย็น
  ⚠️ **แลกกับความเสี่ยง:** วันไหนลืมอัปเดต ใบจะดู "นับครบแล้ว" ทั้งที่ยังไม่ได้นับ
- **วันย้อนหลังที่ไม่เคยมีใบ = ไม่สร้างให้** (จะได้ตัวเลขของวันอื่นมาแทนของจริงที่ไม่เคยนับ)
  → แสดงพรีวิวรายการสินค้าพร้อมข้อความว่าวันนั้นไม่ได้นับ
- **ไปวันอนาคตไม่ได้** — ปุ่ม › disabled + ปฏิทินก็เด้งกลับ

#### ⏳ แท็บ "เบิกรอเซ็น" — แทนชีต `เบิกรอเซ็น` (sql/182 · ต้องรันมือ)

> 🔴 **อย่าย้ายไปรวมกับหน้า "เบิกสินค้า" และอย่าลบทิ้งเพราะคิดว่าซ้ำซ้อน**
> เคยมีคนคิดว่า "ของออกไปแล้วก็ตัดเลยสิ" — คำถามคือ **ตัดที่ไหน**
> ตัวเลข "ยอดในระบบ" ที่เอาไปเทียบมาจาก**ไฟล์ของระบบหลังบ้าน**ที่ ERP เขียนกลับไม่ได้
> ตัดใน ERP ยังไงยอดฝั่งที่เทียบก็ไม่ขยับ

- **ปัญหาที่แก้:** ช่วง "ของออกจากชั้นแล้ว แต่หลังบ้านยังไม่ตัดยอด (รอเซ็นอนุมัติ)"
  ถ้าไม่บวกกลับ ใบตรวจนับจะฟ้อง "ของหาย" ทุกวันทั้งที่ไม่หาย

  | ของบนชั้น 100 · เบิกออก 10 รอเซ็น | คำนวณ | ผล |
  |---|---|---|
  | ไม่บวกกลับ | 90 − 100 | −10 → "ของหาย 10" ❌ |
  | บวกกลับ | (90+10) − 100 | 0 → "ตรงกัน" ✅ |

- **ทุกแถวในตาราง = "ยังรอเซ็น" เสมอ ไม่มีคอลัมน์สถานะ** — เซ็นอนุมัติแล้ว = **user ลบแถวทิ้ง**
  (ตามที่ชีตเดิมทำ · เจ้าของงานยืนยัน) → มีแถวอยู่ = ต้องบวกกลับ · ลบแถว = ยอดหลุดออกเอง
- แถวเพิ่มรายการเรียงตรงกับคอลัมน์ชีตเดิม: **วันที่ · สินค้า · จำนวน · ผู้เบิก · หมายเหตุ**
  · Enter ในช่องจำนวน = กด ＋ เพิ่ม · หลังเพิ่มคงวันที่+ผู้เบิกไว้ (มักเบิกหลายตัวให้คนเดียวกัน)
  · สินค้าเลือกจาก `stock_items` (master กลาง) + snapshot ชื่อ/รหัสลงแถว
- เพิ่ม/ลบแถว → เรียก `pullIssue({silent:true})` ทันทีถ้ากำลังดูใบของวันนี้ ไม่ต้องรีเฟรช
- 🔴 **ตารางแยก `stock_check_issues` ไม่ใช้ `withdraw_txn_lines`** — เพราะแถวที่นี่ถูก**ลบทิ้ง**
  เมื่อเซ็น ถ้าไปเก็บรวมกัน การลบจะทำให้บิลเบิกจริงหายจากรายงานรายเดือน/ประวัติของหน้าเบิกสินค้าด้วย
  · ชีตเดิมก็แยกกัน: `เบิกรอเซ็น` อยู่ในเล่ม Stock F.3 ส่วน `Withdraw_DATA` แยกเล่ม
- ⚠️ **ถ้าวันหน้าเริ่มใช้หน้าเบิกสินค้ากับคลังนี้ด้วย** (และยังผูก catalog ไม่ครบจึงไม่ตัดสต็อก)
  ต้องบวกยอดจาก `withdraw_ledger` ที่ `movement_id IS NULL` เข้ามาใน `pullIssue()` เพิ่ม
  ไม่งั้นของพวกนั้นจะขึ้นเป็น "ของหาย"
- `loadIssues()` **ห้าม throw** — ถูกเรียกใน `init()` ก่อน `loadDay()` ถ้าระเบิด
  แท็บตรวจนับทั้งแท็บจะไม่โหลดตามไปด้วย (ยังไม่รัน sql/182 = โชว์คำแนะนำในตารางแทน)


### 📦 รายการสินค้า — master กลางของ 3 หน้า (`stock_items`)
- **หน้าตรวจนับ Stock F.3 คือที่เดียวที่แก้ได้** (ปุ่ม 📦 รายการสินค้า · perm: `stock_items_manage`)
  หน้าเบิก และหน้ายืม/คืน มีปุ่ม ⚙️ แต่เด้งมาที่นี่ (`stock-check.html?items=1`) — ไม่เปิดให้แก้ 2 ที่
- ฟิลด์: **รหัส · ชื่อ · หมวด · ลัง→ชิ้น · ราคา · ลำดับ · เปิดใช้ · ผูก catalog**
  - `item_name` **unique** — ทุกชีตต้นทาง lookup ด้วยชื่อล้วน · index ใช้
    `lower(regexp_replace(btrim(...),'\s+',' ','g'))` ให้ตรงกับ `norm()` ใน .js เป๊ะ
  - `item_code` **ไม่ unique** — ชีตมี SKU ซ้ำจริง (`TS0001.1` ใช้ 2 แถว) บังคับ unique แล้ว import ล้มทั้งชุด
  - `sort_order` เป็น **NUMERIC** ไม่ใช่ INT — ชีตใช้ทศนิยมจัดกลุ่ม (3.1 · 5.2) เพื่อแทรกกลางกลุ่มได้
  - `pieces_per_box` **> 0 เสมอ** (0/ว่างในชีต = ขายเป็นซองไม่มีลัง → เก็บ 1)
    ถ้าเก็บ 0 สูตร ลัง × ตัวคูณ จะกลืนจำนวนลังหายเงียบ
  - `product_id` (nullable) = สะพานไป catalog · **ผูกแล้วเท่านั้น**ที่เบิกจะตัดสต็อกจริง
    และใบตรวจนับกด "ดึงยอดในระบบ" ได้ · โมดัลโชว์ 🔗 / ⛓️‍💥 ให้เห็นสถานะทุกแถว
- **คอลัมน์ราคาซ่อนเป็นค่าเริ่มต้น** — หน้าตรวจนับไม่ใช้ราคา · ติ๊ก "💰 แสดงราคา" เพื่อเปิด
  (จำค่าไว้ที่ `localStorage.sc_im_show_price`) · ซ่อนด้วย **CSS `display:none` เท่านั้น
  ห้ามลบ input ออกจาก DOM** — `imBuildRow()` อ่านค่าจาก input ตอนบันทึก
  ถ้าลบทิ้ง กด 💾 ครั้งเดียวราคาทั้งตารางจะกลายเป็น 0 แล้วมูลค่าในหน้าเบิก/ยืม-คืน พังตาม
- **แก้ในโมดัลแล้วตารางข้างหลังอัปเดตทันที** — `refreshItemsEverywhere()` (โหลด master ใหม่ +
  วาดโมดัล + `renderAll()`) เรียกท้ายทุก add/save/delete · ไม่ต้องปิดโมดัลหรือรีเฟรชหน้า
  · ปิดโมดัลด้วย **ESC** ผ่าน modalManager.js ซึ่งลบ class `.open` ตรง ๆ ไม่เรียก
  `closeItemManager()` → ต้องใช้ **MutationObserver เฝ้า class ของ `#itemModal`**
  ผูกกับปุ่มปิดอย่างเดียวไม่พอ กด ESC แล้วตารางจะค้างข้อมูลเก่า
- ลบสินค้า = FK `ON DELETE SET NULL` ทั้ง 3 ตาราง — บรรทัดเก่ายังอยู่และยังนับในรายงาน
  (ใช้ชื่อ/ราคา snapshot ตอนนั้น) · โมดัลนับจำนวนบรรทัดที่กระทบมาเตือนก่อน
- **import master:** [scripts/import-stock-items.js](../../scripts/import-stock-items.js) —
  อ่าน `DATA_STOCK.xlsx` ชีต 🧴Products (49 รายการ) · dry-run ก่อน · `--apply` ถึงเขียนจริง ·
  **upsert ด้วยชื่อ** จึงรันซ้ำได้ ไม่เกิดแถวซ้ำ
- ⚠️ **ไม่ได้ใช้ catalog `products` เป็น master** เพราะ catalog มีแต่เสื้อ/ของพรีเมียม (153 รายการ)
  ไม่มีสินค้าจริงที่ 3 หน้านี้ใช้ (4Soil · Lean C · EYE+ · Amino Black) เลยสักตัว — ตรงกัน 0/30
  และ 3 หน้านี้ต้องการฟิลด์ที่ catalog ไม่มี (ตัวคูณลังตายตัวต่อสินค้า · ลำดับในฟอร์มกรอก)

**ตาราง:** `products`, `categories`, `product_units`, `product_images`, `warehouses`(+zones/locations/bins), `stock_movements`, `stock_balance`, `units`, `app_settings`, `delivery_customers`, `delivery_orders`, `stock_items`, `borrow_persons`, `borrow_txns`, `borrow_txn_lines`, `withdraw_categories`, `withdraw_txns`, `withdraw_txn_lines`, `stock_check_sessions`, `stock_check_lines`

## 2. Transactions (เอกสาร)

> ⚠️ สำคัญ: PO/SO/REQ **ไม่** auto-create `stock_movements` ตอน approve/confirm — สต็อกถูก reserve เท่านั้น ต้องบันทึก movement (รับเข้า/จ่ายออก) แยกเอง

### Purchase Order (PO) — `transactions/purchase_order/`
- `po-list.html` + `po-form.js`/`po-list.js`
- เลือก supplier + warehouse (card grid, filter ตาม country ของ user); line items: product/qty/unit_price + badge สต็อก
- เลขที่: `PO-YYYY-MM-nnnnn`; สถานะ DRAFT → APPROVED → RECEIVED (CANCELLED)
- **ตาราง:** `purchase_orders`, `po_items`, `suppliers`

### Sales Order (SO) — `transactions/sales_order/`
- `so_form.html/.js`
- 2 ประเภท: **SALE** (`SO-YYYY-`, ต้องเลือกสมาชิก) / **INTERNAL** (`INT-YYYY-`, ไม่มีลูกค้า)
- **ขายให้สมาชิก MLM เท่านั้น** — ไม่มีตาราง customers แยก (ใช้ `members`)
- line: product + unit + qty + price; ส่วนลด (จำนวน/%); VAT 7% (default on SALE)
- สถานะ DRAFT → CONFIRMED → DELIVERED (CANCELLED)
- **ตาราง:** `sales_orders`, `so_items`, `members`

### Requisition (REQ) — `transactions/requisition/`
- `requisition-list.html` + `requisition-form.js`/`requisition-list.js`
- เบิกสินค้าภายในต่อแผนก; เลือก dept (auto จาก user.department) + warehouse + purpose
- เลขที่: `REQ-YYYY-MM-nnnnn`; สถานะ DRAFT → PENDING → APPROVED → ISSUED (CANCELLED); workflow อนุมัติ
- **ตาราง:** `requisitions`, `requisition_items`, `requisition_purposes`, `departments`

### Petty Cash (เงินสดย่อย) — `transactions/petty_cash/`
- `petty-cash-list.html` + `petty-cash-form.js`/`petty-cash-list.js`
- ledger รับเข้า/ใช้จ่าย; เลือกบรรทัด → ออกเอกสาร:
  - สรุป Petty Cash
  - **ใบรับรองแทนใบเสร็จ**
  - **ใบสำคัญเงินสดย่อย**
- ใช้ `js/utils/bahtText.js` แปลงจำนวนเงินเป็นคำอ่านไทย
- letterhead จาก `trip_doc_letterheads` + company info จาก `app_settings`
- **ตาราง:** `petty_cash_books`, `petty_cash_items`, `trip_doc_letterheads`, `app_settings`
